# План улучшения Telegram-бота `blood-pressure-bot`

## Безопасность

| № | Проблема | Описание | Предложение |
|---|----------|----------|-------------|
| 1 | **Нет таймаутов на HTTP-клиент** | `http.Client{}` без `Timeout` — при зависании API Telegram горутина зависнет навсегда | `&http.Client{Timeout: 10 * time.Second}` |
| 2 | **Нет таймаутов на контекст** | Везде `context.Background()` — SQLite-запросы не ограничены по времени | Использовать `context.WithTimeout` (5s) |
| 3 | **Нет rate limiting** | Бот не защищён от спама сообщениями | Добавить `rate.Limiter` на пользователя |
| 4 | **Нет `recover()` в цикле событий** | Паника в горутине уронит весь бот | `defer recover()` в `Start()` и `handleEvents` |
| 5 | **Логи не санированы** | Текст сообщения и username пишутся в лог как есть | Обрезать длину и управляющие символы |
| 6 | **Файл БД с правами по умолчанию** | SQLite в `data/` лежит с default permissions | Установить `0600` или через volume |
| 7 | **Нет graceful shutdown** | При `SIGTERM`/`SIGINT` — жёсткое убийство, возможна потеря данных | `signal.NotifyContext` + корректное завершение цикла |

## Архитектура и Best Practices

| № | Проблема | Описание | Предложение |
|---|----------|----------|-------------|
| 8 | **Нет тестов** | Ни одного теста во всём проекте | `go test` + `testify` + `httptest` для Telegram API |
| 9 | **Нет CI** | Нет GitHub Actions или Makefile test target | `.github/workflows/ci.yml` с `go test ./...` и `go vet` |
| 10 | **Offset не сохраняется** | После рестарта бот переобрабатывает старые update'ы | Сохранять offset в SQLite или в файл |
| 11 | **Hardcoded timezone** | `Asia/Yekaterinburg` зашита в коде | Вынести в `TG_TIMEZONE` (env var) |
| 12 | **Hardcoded пути** | Путь к БД — константа в `main.go` | `STORAGE_PATH` (env var) |
| 13 | **Magic строки дня** | "утро"/"день"/"вечер" размазаны по `commands.go` | Константы или отдельный тип `DayPart` |
| 14 | **Sleep вместо long polling** | `time.Sleep(1s)` при отсутствии событий | Использовать параметр `timeout` в `getUpdates` |
| 15 | **Нет структурированного логгирования** | Только `log.Printf` | `slog` (stdlib, Go 1.21+) |
| 16 | **Смешение уровней в storage** | `Show()` возвращает готовую строку вместо данных | Вернуть `[]Pressure`, форматирование — в presentation layer |
| 17 | **Нет валидации диапазонов** | Показатели 999/999/999 проходят проверку | sys 60–250, dia 30–200, hr 30–250 |
| 18 | **`getPressures` не проверяет кол-во** | Нет гарантии ровно 3 чисел | Проверять `len(result) == 3` |
| 19 | **Мёртвый код** | `ErrNoSavedPages` определён, нигде не используется | Удалить |
| 20 | **Неструктурированная конфигурация** | Параметры разбросаны по константам, `.env`, `os.Getenv` | Единый `Config` struct, читаемый из env |
| 21 | **Нет мониторинга** | Нет метрик (кол-во сообщений, ошибки, время ответа) | Prometheus-экспортер или хотя бы `expvar` |
| 22 | **Нет retry-логики** | Временная ошибка Telegram API = потеря события | Retry с exponential backoff |

## Мелкие замечания

| № | Замечание |
|---|-----------|
| 23 | `Consumer.Start()` — value receiver, `handleEvents` — pointer; унифицировать |
| 24 | Импорт `tgClient` из-за конфликта имён — переименовать пакеты или использовать один нейминг |
| 25 | Установка `tzdata` в Dockerfile избыточна при COPY зон из builder |
| 26 | `go-sqlite3` требует CGO → рассмотреть `modernc.org/sqlite` для полностью статической сборки |

## Приоритет реализации (рекомендация)

1. Graceful shutdown + recover (жизнеспособность)
2. Таймауты HTTP-клиента и контекста (безопасность, утечки)
3. Сохранение offset (корректность)
4. Rate limiting (безопасность)
5. Конфигурация через env (гибкость)
6. Тесты + CI (качество)
7. Структурированное логгирование (наблюдаемость)
