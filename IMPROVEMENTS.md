# План обновления проекта на Go 1.26

## 1. Версия Go

- `go.mod`: `go 1.25` → `go 1.26.0` (через `go get go@1.26`, это же обновит `go.sum`).
- `Dockerfile`: `FROM golang:1.25` → `FROM golang:1.26`.

## 2. Зависимости

- `go get github.com/mattn/go-sqlite3@v1.14.49` — актуальный патч (требует `go 1.21`, совместим с 1.26). Это cgo-зависимость, обновление снизит риск при новом тулчейне.

## 3. Модернизация кода под Go 1.26

- `errors.AsType[*APIError](err)` вместо `errors.As(err, &apiErr)` — 3 места в `clients/telegram/telegram_test.go:102,121,209` (типобезопасный, быстрее).
- `go fix ./...` — прогнать новые modernizers 1.26, отревьюить дифф, применить только осмысленные правки; если ничего не применится — отказ.
- `new(expr)` не применять: конструкторы уже используют идиому `&T{...}` (`telegram.go:50`, `notifier.go:36`, `types.go:37`), перевод в `new(...)` — чистый шум без выгоды.
- Остальное из 1.26 неприменимо к проекту: `ServeMux 301→307` / `net/url` (используется `net/http`-клиент, не сервер), crypto, reflect-итераторы, `bytes.Buffer.Peek` (в CSV — `strings.Builder`), `slog.MultiHandler` (логгер — `log`). Код менять для совместимости не требуется — ломающих изменений для проекта нет.
